First-run setup

Three service credentials for the hosted setup.

For the public hosted relay, ClassSync only needs a Fireflies API key, a Gemini API key and a Notion integration token. The app discovers the relay registration mode automatically; the hosted relay is open for account creation, so there is no separate ClassSync setup token to obtain.

Keep secrets private. Never put API keys, recovery codes, invite or registration codes, or webhook signing secrets in screenshots, GitHub issues or chat messages. ClassSync keeps service credentials in OS secure storage.

4. Finish the nine-screen wizard

  1. Welcome: review what you need, or choose Use recovery code if this is an additional device for an existing account.
  2. Relay: keep the hosted relay selected for the normal setup. ClassSync detects whether a relay uses open, invite or token registration. Only custom relays may ask for a code.
  3. Account: enter the owner's display name, create the private ClassSync account and save the recovery code.
  4. Fireflies: paste and test the API key. ClassSync also shows the account-specific Webhooks V2 URL and signing secret.
  5. Gemini: paste and test the API key and choose the summary model.
  6. Notion: paste the token, discover the shared databases and select Lista de Cadeiras plus Histórico de Resumos.
  7. Academic: optionally connect ISEP Portal and Moodle, or skip them for later.
  8. Automation: choose notification and platform background-processing preferences.
  9. Ready: review the verified connections before the first sync.

5. Configure the Fireflies webhook

Use the exact account-specific URL and signing secret shown by ClassSync in Fireflies Webhooks V2. Subscribe only to meeting.transcribed. Each ClassSync account gets its own webhook values.

Optional academic connections

The Academic step can connect ISEP Portal and Moodle, or you can configure them later under Academic → Connections. Portal data stays in the local offline cache and does not pass through the ClassSync relay. Moodle stores the exchanged app token rather than the submitted password.

Notion database requirements

  • Lista de Cadeiras: Nome (or Name), Ano, Semestre, Status.
  • Histórico de Resumos: Nome, Data, Cadeira.
  • Only subjects whose Status is In progress are classification candidates.
Recommended metadata. Let ClassSync add the optional Fireflies ID rich-text property. It makes reconciliation safer across devices and interrupted publishes.

Class identification and retries

Under Settings → AI & summaries, choose whether Gemini should identify classes automatically. Turning it off makes new lectures wait for your manual choice. You can change an identified class later; ClassSync updates its owned content on the same Notion page instead of creating a duplicate.

Moving to another device

Choose Use recovery code on Welcome. Recovery restores the encrypted shared configuration for that account, including configured Fireflies sources, Gemini/Notion keys and academic credentials when present in the synced snapshot. It does not require an invite or registration token.

For an account on a self-hosted relay, expand Custom relay and enter the existing relay URL before recovering. Full transcripts and generated summaries are not copied between devices; bounded status and Notion-link metadata are.

App updates

Current builds can check public GitHub releases when the app opens and from Settings → App updates & widget. Public releases normally require no GitHub token. If GitHub rate-limits a device, you can optionally provide a fine-grained token with only Contents: read; it stays in OS secure storage on that device.

When you accept an update, ClassSync downloads the matching installer or APK, verifies the published SHA-256 checksum and starts the platform installer. Android still requires normal system approval for sideloaded APK updates.
